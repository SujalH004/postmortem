# 👻 PostMortem: The Git Forensics Medium

## 📖 Overview

In every growing codebase, critical defensive logic is occasionally deleted during routine refactoring because static analysis assumes nothing calls it directly. Months later, when a rare edge case occurs—such as a leap-year billing rollover, a cryptographic timing check, or a concurrent checkout spike—that missing guard causes a production outage.

**PostMortem** is an open-source, privacy-first forensic workbench that helps developers diagnose deleted or vulnerable code, understand the exact invariant it protected, and generate a verified restoration patch—running **100% locally** on your machine.

## ✨ Key Features

* **🕯️ 2-Phase Cyber-Séance Studio**: Drop in any `.py`, `.js`, `.ts`, `.go`, or `.diff` file (or explore three built-in production bug scenarios) in a focused, distraction-free web interface.
* **🔬 Ground-Truth Line Ledger**: Automatically parses and numbers every line of code (`[tag:L1]`, `[tag:L2]`, ...) before sending context to the AI model, eliminating line-offset math errors.
* **🔮 Local Google Gemma 3 (`gemma3:1b`) Autopsy**: Diagnoses the root vulnerability, calculates a severity score (`0–100`), and explains what breaks in production using verifiable line citations.
* **🛡️ Stage 2 Exorcism Shield (Anti-Hallucination Guardrail)**: Cross-checks every `[tag:L#]` citation generated by the model against the Ground-Truth Ledger and blocks any fabricated line references in real time.
* **🩹 Side-by-Side Resurrection Patch & Invariant Checks**: Compares the vulnerable state against the hardened fix, validates three automated safety invariants, and exports a clean Markdown incident report (`.md`).

## 🚀 Quickstart

### 1. Start Local Gemma 3 (`gemma3:1b`) with Ollama
Install [Ollama](https://ollama.com) and pull Google's lightweight `gemma3:1b` model:
```bash
ollama pull gemma3:1b
```

### 2. Launch the Web Studio
Open **`index.html`** directly in any modern browser (Chrome, Edge, or Firefox)—no build step or package installation required:
1. Click **`🔄 Sync`** in the top header to connect to your local Ollama instance (`http://localhost:11434`).
2. Upload a file, paste a `git diff`, or select one of the built-in sample ghosts (`👻 Leap-Year Billing Outage`, `🔐 HMAC Timing Bypass`, or `⚡ Wallet Double-Spend Race`).
3. Click **`👻 Summon Ghost & Run Autopsy ➔`** to view the diagnosis, verify the restoration patch, and ask follow-up questions.

### 3. Run the Terminal CLI (`postmortem.py`)
You can also scan local Git repositories and generate restoration patches directly from your terminal:
```bash
python postmortem.py --model gemma3:1b --generate-patch
```

# 🧠 System Architecture

# System Architecture Explained

This system finds security flaws in code, checks its own findings so it can't invent false ones, and produces a fix. It runs entirely on your own machine.

## Stage 1: Deterministic AST & Diff Indexer
- **Input:** a unified diff (a code change) or a source file.
- **Parsing:** it reads the code's structure (the AST) and finds defensive branches such as input checks, validations, and error handling.
- **Line tagging:** every line gets a permanent label like `[tag:L12]`. These labels form a master ledger of what exists in the code.
- **Deterministic:** the same input always gives the same output, with no AI involved. This makes it a reliable source of truth.

## Stage 2: Local Gemma 3 Engine
- **Model:** `gemma3:1b`, a small AI model running locally through Ollama.
- **Prompt format:** it uses Gemma's native `<start_of_turn>` instruction format, so the model follows instructions more reliably.
- **Task:** it studies the tagged code and explains the root cause of each vulnerability, citing line tags as evidence.
- **Offline:** no code leaves your machine, which protects privacy and sensitive source code.

## Stage 3: Exorcism Citation Verifier
- **Purpose:** AI models can cite lines that don't exist. This stage catches that.
- **Check:** every `[tag:L#]` the model cites is compared against Stage 1's ledger.
- **Quarantine:** any citation that doesn't match is isolated and never shown to the user.
- **Result:** only findings grounded in real code reach the output.

## Stage 4: Patch Synthesizer
- **Patch:** it generates a copy-ready fix that restores the missing or broken defenses.
- **Report:** it also writes a Markdown postmortem covering what went wrong, where, and how the patch resolves it.

## Why This Design Works
- **Separation of duties:** deterministic code handles facts, and the AI handles reasoning.
- **Built-in verification:** the AI's output is checked before anyone sees it.
- **Privacy:** everything runs locally.
- **Actionable output:** you get a fix and documentation, not just a warning.

## Flow in One Line
Code → tagged line ledger → AI diagnosis → citation check → patch and report.
